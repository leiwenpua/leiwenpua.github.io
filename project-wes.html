WES Assembly System

Python BWA-MEM GATK Tkinter Bash

Project Background

Developed as my Master’s Final Year Project, ASASWES was created to address a critical bottleneck in the laboratory's handling of massive Whole Exome Sequencing (WES) datasets for the MyGenom project.

"The primary goal was to liberate researchers from the terminal."

Previously, the workflow required manual command-line execution and constant monitoring, tethering experts to their computers for hours. ASASWES transforms this fragmented process into an end-to-end, automated pipeline. By replacing labor-intensive manual tasks with a modular framework and a real-time monitoring GUI, the system enables users to trigger a run and focus on high-value biological interpretation instead of process management.

Overall Strategy & Logic

The "Central Hub" Architecture

The system utilizes Python 3.11 as the primary orchestration engine. Through a modular design, it integrates complex bioinformatics tools into a unified, automated framework. The core logic focuses on seamless data flow transitions and environment consistency.

Integration Mechanism

  • • Subprocess Pipe: Directly invokes low-level Linux binaries (BWA, GATK, Samtools) via Python's subprocess module.
  • • Dynamic CLI Generation: Parses GUI-captured parameters to dynamically construct command-line strings that strictly adhere to bioinformatics tool syntax.
  • • Asynchronous Threading: Implements multi-threading to decouple heavy computational tasks from the main loop, ensuring the GUI remains responsive and lag-free during long-running processes.

Key Functional Modules

  • • Automated IO Handling: Manages the complete lifecycle of data transformation (FASTQ → BAM → VCF) including intermediate file cleanup and directory structuring.
  • • Real-time Progress Tracking: Intercepts and parses Standard Output (Stdout) from active tools to visualize real-time progress via GUI progress bars.
  • • Standardized Error Logging: Features automated exception catching and detailed log generation, essential for debugging large-scale datasets (2GB+).

Pipeline Execution Logic

Stage Key Tools Logical Objective
Pre-alignment FastQC, Picard (FastqToSam) Quality control of raw reads, adapter trimming, and conversion to unmapped BAM (uBAM) format.
Alignment BWA-MEM, Samtools Efficient mapping to the GRCh38 human reference genome and FAI indexing for rapid retrieval.
Refinement Picard (MarkDuplicates), GATK (BQSR) Identification of PCR duplicates and Base Quality Score Recalibration to minimize systematic errors.
Variant Calling GATK (HaplotypeCaller), ANNOVAR Germline variant detection and functional annotation (converting coordinates to biological/clinical significance).

Future Directions & Scalability

Containerization (Docker)

Transitioning the pipeline into a Docker image to eliminate "dependency hell." This ensures the complex mix of Java, Python, and C++ tools runs identically across any OS with zero manual configuration.

Modular Refactoring

Refactoring the current script architecture into a structured package. By decoupling configuration, UI logic, and core bioinformatics modules, the system will become more maintainable and unit-testable.

Cloud-Native Transition

Moving towards a cloud-based execution model (e.g., AWS Batch or Nextflow Tower integration). This would allow the lab to scale from processing single samples to hundreds of genomes simultaneously using elastic compute.

Extended Validation

Expanding the validation phase using high-throughput benchmarks. This involves stress-testing the pipeline with diverse population datasets to further refine the Precision and Recall metrics for rare variant detection.

Intelligent Decision Logic

Implementing automated "Quality Gates" between pipeline stages. The system will programmatically evaluate FastQC metrics and cross-check data integrity; if quality thresholds are not met, the pipeline will auto-terminate or trigger specific re-processing parameters to save computational costs.

Dynamic Resource Heuristics

Integrating hardware-aware logic that analyzes input FASTQ file sizes to automatically calculate the optimal threads and memory allocation. This prevents "Out of Memory" (OOM) errors and ensures the most efficient use of Ubuntu's system resources.
